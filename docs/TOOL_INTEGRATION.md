# Trusted tool integration

The reference integration requires Python 3.10+, a trusted local SQLite state store with schema resource_state(resource TEXT PRIMARY KEY, revision INTEGER, value TEXT), a trusted separate replay database, and a shared secret generated by the relying party. No remote dependencies or LLM API account are needed.

```python
from contextlib import closing
from pathlib import Path
from tempfile import TemporaryDirectory
import secrets
import sqlite3
from openactionproof.durable_replay import DurableReplayGuard
from openactionproof.tool_session import verify_tool_call

with TemporaryDirectory() as tmp:
    db = Path(tmp) / "state.db"
    with closing(sqlite3.connect(db)) as c:
        c.execute("CREATE TABLE resource_state(resource TEXT PRIMARY KEY, revision INTEGER, value TEXT)")
        c.execute("INSERT INTO resource_state VALUES ('target', 0, 'old')")
        c.commit()
    guard = DurableReplayGuard(Path(tmp) / "replay.db", initialize=True)
    def trusted_tool():
        with closing(sqlite3.connect(db)) as c:
            c.execute("UPDATE resource_state SET revision=revision+1,value='new' WHERE resource='target'")
            c.commit()
    result = verify_tool_call(
        database=db, guard=guard, key=secrets.token_bytes(32),
        task_id="demo", observer_id="observer", resource="target",
        expected_value="new", actor=trusted_tool,
    )
    print(result.actor_status, result.verdict)
```

Expected: RETURNED STATE_MATCHED_UNATTRIBUTED. Do not mistake the verdict for proof of actor causality. The callback return is ignored; exception details are discarded. An exception after a committed write can still leave matching state. If the initial observation is unavailable, no callback is invoked; if the final observation is unavailable, the verdict is indeterminate.

This synchronous API accepts a trusted callback, not an untrusted agent. It cannot interrupt a hanging callback and does not isolate process privileges. The before/after observation windows must not overlap; the reference implementation may wait for the first window to expire, adding up to the configured window duration. No distributed clock or stale replica guarantee, rollback-resistant database, or hardened secret custody is provided. Retrying a tool with an indeterminate verdict may duplicate effects; use application-level idempotency. A real agent-framework adapter and independent verification remain future work.
