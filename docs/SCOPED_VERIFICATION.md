# Scoped SQLite write verification (experimental)

The post-freeze operation scope evaluation demonstrates that a correct single-resource verdict cannot establish absence of side effects on other resources or exactly one revision increment. See benchmarks/POST_FREEZE_SCOPE_RESULTS.md; those negative results remain unchanged.

The optional scope module checks a caller-pinned complete before/after snapshot of a dedicated resource_state table. The host supplies a trusted initial mapping of resource names to (revision, string value), target, and desired value. The expected final snapshot increments only the target revision by one and changes only its value. Every other row must remain identical. Unexpected rows and missing rows cannot match. An initial mismatch prevents actor invocation. Use verify_scoped_write with a trusted synchronous callback, HMAC key and dedicated DurableReplayGuard. The result separates actor status from observed-state verdict; PRECONDITION_MISMATCH is not an actor failure. STATE_MATCHED_UNATTRIBUTED is a matching scoped snapshot, not causal proof.

This is a bounded local reference adapter (up to 256 rows, 16 KiB UTF-8 per value, nonnegative signed-64-bit revisions). It uses a separate read-only SQLite connection in the same process, not a security sandbox. Rows and revision counters must be honest, and the caller must independently know the initial state. Effects outside the table, transient changes restored before observation, revision manipulation, database rollback, concurrent actors producing an indistinguishable state, and untrusted storage/keys remain outside the contract. The actor callback cannot be interrupted by this adapter. It does not guarantee exactly-once execution or operation-wide absence of arbitrary side effects. An indeterminate result does not permit automatic retry.

Local Python 3.13.5: 91/91 unit tests passed in 22.738 seconds (8 new scope tests). The collateral-write and duplicate-write cases from the frozen evaluation now produce STATE_MISMATCH in the new scope adapter's regression tests. An unexpected inserted row also produces STATE_MISMATCH. These are corrective regression tests on known classes, not a second held-out evaluation. Additional independently authored scope tests and trust-boundary review are needed before broad claims.

Reproduce: PYTHONPATH=src python -W error::ResourceWarning -m unittest discover -s tests -q
